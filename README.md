# 心屿 OS V3.7 · 本地 AI 虚拟陪伴世界（Android / Flutter）

这是基于 V3.6「全部已知编译及测试修复」完整工程制作的 **V3.7 源码版本**，并非已编译的 APK。继续使用已有 GitHub Actions、安卓应用签名与本地数据存储；不需要自建服务器，但云端模型 API 仍需要联网、用户自己的 API Key 与模型账户额度。

## V3.7 主要变更

- **聊天生成控制**：取消正在生成的请求后立即释放输入操作；通过每个会话的请求序号阻止被取消的旧回复再次写入；编辑自己的消息并重新发送，不必等旧回复完成。重新生成会先移除当前回复、流式显示新版本，历史文本保留在回复版本中；失败时尝试恢复原有回复。
- **输出格式与时间**：可以指定自动、Markdown、JSON、纯文本输出；当 JSON 不合法时最多尝试一次格式修正（会额外消耗 API 用量）。每次请求的角色提示词携带设备当前日期与时间信息；系统时钟错误则会影响时间。提供本机 `/time` 与 `/calc 6*7` 等简单离线工具。
- **AI 朋友圈**：增加用户授权的前台定期动态生成设置；仅在打开/使用 App 且符合时间间隔时尝试调用，关闭或后台休眠时不保证自动发布，也不会绕过用户授权。
- **虚拟世界**（仅本机模拟）：星币钱包、每日签到、虚拟红包、虚拟礼物商店/购物车/订单、宠物喂养与成长、共同经历时间线。虚拟余额无法提现、兑换或转账为真实货币；不连接淘宝、京东或实际支付系统。
- **一起看**：从本机选取视频在应用内播放，旁边可向指定 AI 角色聊天；AI 仅获得文件标题与播放位置等上下文，**并未实时看到画面、听见声音**。
- **一起听**：沿用应用内可跨页面播放的本地音乐功能；不承诺锁屏或进程被系统终止后的持续播放。
- **角色连续性**：将部分钱包、宠物、订单和共同经历事件摘要纳入对应角色的聊天上下文，明确标明这是模拟世界。
- **保留 V3.6**：激活码校验、API 连接、人物设定与沉浸剧情、图片与 Token、消息操作、朋友圈评论、桌面拖动/美化、背景、字体、头像等功能。

## 构建 APK（无需自行安装 Flutter）

1. **先备份手机里的重要数据**，不要卸载已经安装的旧版本。
2. 解压「V3.7 完整工程」后，将根目录内的文件与文件夹复制到 GitHub Desktop 克隆的 `XinyuOS-Android` **仓库根目录**（不是额外套一层文件夹）。推荐直接按相对路径覆盖 `lib/`、`test/`、`tools/`、`pubspec.yaml` 等。
3. `.github/workflows/android-build.yml` 位于仓库根目录的隐藏 `.github` 目录中；继续沿用你之前配置的 Actions Secret `XY_RELEASE_SIGNING_BUNDLE`，不要重新生成 APK 签名密钥。
4. GitHub Desktop：**Commit to main → Push origin**；然后打开 [GitHub Actions](https://github.com/BIGEAR236/XinyuOS-Android/actions) 检查 `release-apk`。只有编译、分析、测试均成功时才下载新的 APK。
5. **先在自己的测试手机上覆盖安装**，测试激活、API、原有聊天记录和新玩法，确认稳定后再分享给体验者。

如果你用「从 V3.6 升级补丁」，必须保证仓库里的 V3.6 已含之前对 `ui_proactive.dart`、`ui_contacts.dart` 和 `api_client.dart` 的修复。如不确定，推荐完整工程。

## 重要限制

- **未在本环境执行 Flutter 编译、真机安装或真实模型 API 联调。** 本环境只运行 Python 静态检查和离线激活签名向量验证；不能承诺 GitHub Actions 一次性编译成功。
- 真实 API Key 仅由用户在手机设置，不应上传 GitHub。公开工程不包含签发激活码的管理员私钥及安卓签名密钥。
- 虚拟红包与购物为非现实场景，不能代替真实支付、下单或商品配送。
- 模型对格式要求不是绝对可靠；严格 JSON 通过本地校验和有限重试提高成功率，但额外重试会产生费用。
- 不部署服务器意味着 **AI 不会在 App 完全关闭时可靠地持续调用 API、自动社交或跨设备同步**。
