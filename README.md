# 心屿 OS V3.2 — 安卓功能升级工程

本版以已经通过 GitHub Actions 编译的 V3.1 激活版为基础升级，**不能把源码压缩包当作 APK 安装**。请在你的私人 GitHub 仓库中替换对应文件，然后由 Actions 重新生成 Release APK。

## V3.2 改进

1. 中转站兼容：自定义 OpenAI Chat Completions HTTPS 接口、接受 `/v1` 或完整 `/chat/completions` 地址、可选 Bearer/x-api-key、提供真实请求地址预览与错误诊断。只连接可信中转站，它会看到用户 API Key 和聊天内容；不承诺兼容所有私有协议。
2. 流式对话：兼容 OpenAI 格式、Claude Messages 事件和 Gemini SSE 流，允许关闭流式；回复可以边生成边展示。真实生成速度仍由网络、转发站与模型决定。
3. 人格对话：系统提示词规定人格资料只作为背景、回答新问题，不照抄文档；每条消息仅携带至多 12 条近期消息，当前最多使用前 8,000 字人设。长人设建议人工精简或分段结构化。
4. 聊天界面：去掉列表分类标题和无关说明，改为最近消息排序、简洁预览和气泡风格。
5. 播放器：一个应用级 AudioPlayer，音乐页进入聊天页继续播放，并提供迷你播放条。**这不是锁屏/退出 App 后的 Android 后台媒体服务**。
6. 虚拟桌面四个图标：支持用户从手机选择图片，应用私有存储。
7. 角色头像：支持从图片选择器导入，自定义头像在聊天、通讯录、群聊和朋友圈使用。
8. 激活：继续验证 XY1 老码，同时支持约 117 字符的 XY2 Ed25519 紧凑签名码（旧格式测试样例约 181 字符）。激活页可一键从剪贴板粘贴；配套私人管理员工具支持每批最多 10,000 个设备编号。

## 升级步骤

1. **备份**当前已经成功编译的仓库及 Release 签名密钥、管理员发码私钥；不要提供给体验者。
2. 用 GitHub Desktop 打开 `BIGEAR236/XinyuOS-Android` 的本地仓库文件夹。
3. 从 `XinyuOS_V3_2_升级补丁_替换文件.zip` 解压，将里面的 `lib/`、`test/`、`test_vectors/`、`pubspec.yaml` 等文件按原有相对位置覆盖到**仓库根目录**。注意要合并文件夹，而不是把整个 ZIP 放进去，也不要新建一层 `XinyuOS_V3_2` 子文件夹。
4. 使用 GitHub Desktop `Commit to main` → `Push origin`，再到 GitHub Actions 查看新运行。原有 `XY_RELEASE_SIGNING_BUNDLE` Secret **保持不变**。
5. 如果构建成功，下载并解压 Artifacts，安装新版 APK 到**已有 V3.1 的手机**（不要卸载旧版），验证旧激活状态、聊天记录、API Key 是否保留。
6. 先验证中转站、流式聊天、图标、音乐和 XY2 测试激活，再邀请新用户。

请保留包名和 Release 签名密钥。版本号由 `3.1.0+2` 提升到 `3.2.0+3`，以便升级安装。

## 保密

公开工程**只含验证公钥**，没有激活签发私钥，也没有 Android release keystore。私人新版管理员发码工具属于单独的私密压缩包，不得复制到 GitHub。不要将任何个人真实 API Key 提交到仓库。

## 客观限制

- V3.2 在此环境中只完成源码静态检查、协议测试样例核验和激活数字签名兼容性核验，**未运行 Flutter SDK 编译、真实设备集成测试或外部真实 API Key**。需要用 GitHub Actions 编译、真机验收后才能对外发布。
- 无自建服务器的一机一码不能远程吊销或全球统计已激活数，也不能绝对阻止修改版 APK；10,000 指**管理员批量签发输入上限**，不是可信的全球授权总数上限。
- 只有支持 OpenAI Chat Completions、Claude Messages 或 Gemini 原生协议的中转站才能按对应方式连接。其他供应商的专有接口需要另写适配器。
- 实际音乐在应用内页面切换时保持播放；后台锁屏播放需另外接入系统媒体服务。
