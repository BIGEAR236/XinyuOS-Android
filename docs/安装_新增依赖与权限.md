# 小雨机 V4.2：合并与验证

以**已经成功编译的 V4.1.2** 为底座，只将本包 `lib/` 内容按相对路径合并覆盖。**不要将整个新目录替换旧 lib。** 保留原 `models.dart`、`pubspec.yaml`、`main.dart`、激活和签名文件。部分旧源码（例如未上传的其他文件）本包无法验证。

## 新增两个 Flutter 依赖

在**原有** `pubspec.yaml` 的 `dependencies:` 下添加以下两行，而不是覆盖旧配置：

```yaml
  speech_to_text: 7.4.0
  flutter_tts: 4.2.5
```

使用 7.4.0 而不是 7.5.0：因为 7.5.0 的最低 Dart 是 3.12，现有项目 SDK 约束为 `>=3.10.0 <4.0.0`。保留已有 `record` 依赖也可以，虽然本次简化语音页不再使用它。

在 `android/app/src/main/AndroidManifest.xml` 的 `<manifest>` 内、`<application>` 前检查存在：

```xml
<uses-permission android:name="android.permission.RECORD_AUDIO" />
<uses-permission android:name="android.permission.INTERNET" />
<queries>
  <intent><action android:name="android.speech.RecognitionService" /></intent>
  <intent><action android:name="android.intent.action.TTS_SERVICE" /></intent>
</queries>
```

`queries` 必须是**一个**，如果已有 `<queries>`，只需合并 `<intent>` 子项，不可添加第二份。手机识别服务可能联网，并非严格离线；将来可集成 sherpa-onnx 离线模型。

## 修改安卓 App 显示名称（不改变应用 ID）

在仓库根目录执行：

```bash
python tools/rename_to_xiaoyuji.py
```

脚本修改 `lib/main.dart` 的 MaterialApp 标题、AndroidManifest.xml 的直接 `android:label` 或现有 `strings.xml` 的 `app_name`。如果你的 Manifest 引用其他资源名，请手动将所引用的字符串改为**小雨机**。**绝不要改 `applicationId`、签名或激活验证。**

## 主要体验

- 数字人：上传本地形象、轻微呼吸浮动动画、Android 系统识别、Android TTS、原角色聊天模型。默认关闭。不是实时口型视频，没有自动克隆音色。原有高级 API 设置仍在本地保存，不再作为必填项。
- 右上角聊天选项：移除“日常回复 1/2/3 条”入口，不触碰历史聊天记录。若之前选过 2/3 条，原存储偏好仍保留。
- 红包：可导入自定义封面；发送后**本地即时收取**并转入 AI 的虚拟账户，显示已领取回执。这只是规则模拟，不是模型实时做出的领取决定；无需额外 API。AI 回复中合法的红包标记会显示领取卡片，玩家点领取时才扣对应 AI 的虚拟余额，并受每日限额约束。
- 礼物：同一 SKU 在商品列表、购物车、赠礼消息里使用同一份本地插画；送出后消耗已购库存。
- 朋友圈：可发表带图动态，也可给旧的玩家或 AI 动态添加本地图片；自动发布权限集中在朋友圈设置中，并保留手动发动态。额外调用模型会收费。后台/杀死进程后**不自动发送**。
- 商城：商品以类别+款式+颜色生成的本地简笔画展示。**不是实物写真或品牌授权图**，但款式与分类对应，离线也能看到。购物车角标已保留，同时有已添加件数提示。

## 验收顺序

```sh
flutter pub get
flutter analyze --no-fatal-infos --no-fatal-warnings
flutter test
flutter build apk --debug
```

然后真机按顺序检查：设置里数字人导入 → 点麦克风并说一句话 → AI 回复并发声；聊天＋发送自定义封面红包；让模型按标记发 10 星币红包并点击领取；购买商品并作为礼物送出；朋友圈发图；商城断网看插画与购物车角标；桌面新名称及 Android 启动器名称。
